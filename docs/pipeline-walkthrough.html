3 serialize_document() src/ententia_idp/llm.py · serialize_document()
Every agent — including all three parallel agents — calls serialize_document(doc) independently at runtime. They each receive the same string from the same ExtractedDocument. This is the exact text appended to every agent's user message before it is sent to Bedrock.
serialize_document() — source llm.py:serialize_document
def serialize_document(doc: ExtractedDocument) -> str: parts = [ f"File: {doc.metadata.source_file_name} | Type: {doc.metadata.file_type} | Pages: {doc.metadata.total_pages}" ] for page in doc.pages: if page.text.strip(): parts.append(f"--- PAGE {page.page_number} ---\n{page.text.strip()}") for table in doc.tables: parts.append(f"--- TABLE (page {table.page}) ---\n{table.markdown}") if doc.figures: fig_lines = [ f" • {f.fig_id} on page {f.page}" + (f": {f.caption}" if f.caption else "") for f in doc.figures ] parts.append("--- FIGURES ---\n" + "\n".join(fig_lines)) return "\n\n".join(parts)

5 Parallel agents agents.py · TaggingAgent, FieldExtractionAgent, SummaryAgent
LangGraph fans out from classification to three nodes simultaneously. Each node calls _run_agent_node(), which builds a fresh context dict from the current state and calls serialize_document(doc) independently. The Annotated[list, operator.add] reducers on errors and agent_metrics safely merge concurrent writes without conflict.
context dict passed to every parallel agent pipeline.py · _run_agent_node()
# built inside _run_agent_node() before calling agent.run() context = { "classification": state["classification"], # ← "Statement of Work" from step 4 "tags": state["tags"], # ← [] (parallel, not yet written) "extracted_fields": state["extracted_fields"], # ← {} (parallel, not yet written) "summary": state["summary"], # ← "" (parallel, not yet written) } # Each agent only READS context["classification"]; it does not use the others

State merge after fan-in: LangGraph collects the three return dicts and merges them into PipelineState. Fields with Annotated[list, operator.add] (errors, agent_metrics) are concatenated; Annotated[bool, operator.or_] (partial) is ORed. All three agents write different top-level keys (tags, extracted_fields, summary) so there is no conflict.
